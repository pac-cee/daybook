# API and implementation research

Checked 27 October 2026. The supplied HTML guide and slides are the requirements authority. The user's SQLite and monochrome requests override the guide's SharedPreferences-only weather-cache example and yellow offline banner.

## API selection

Use **Open-Meteo Forecast API**, `https://api.open-meteo.com/v1/forecast`.

- Official documentation: https://open-meteo.com/en/docs
- Free tier and limits: https://open-meteo.com/en/pricing
- Source and service description: https://github.com/open-meteo/open-meteo
- No API key for the free noncommercial endpoint. The provider lists 10,000 calls/day and no uptime guarantee. Recheck terms before commercial deployment.
- Data attribution is CC BY 4.0. Both apps name Open-Meteo; Weather's information sheet includes the provider domain and license.
- One provider is enough. Fixed coordinates from the guide avoid geocoding, GPS permission and another API dependency.

Requests include the exact four cities from the guide, `timezone=Africa/Kigali`, Celsius, km/h, current temperature, relative humidity, wind, WMO weather code, apparent temperature and day/night. Hourly temperature/code/rain probability and seven daily high/low/code/rain values enrich the interface without another service.

Current readings are required and validated. Numeric values use `num` conversions. Missing, non-finite, structurally invalid or malformed readings fail instead of becoming fake zero values. Optional forecast blocks may be absent. Requests time out after 12 seconds; non-200 statuses fail. The UI offers Retry and only reads the selected city's saved snapshot. A request generation counter prevents an earlier city response from overwriting a later selection.

The app stores the full response via toJson/jsonEncode and parses it on restore. Observation dates/times come from Open-Meteo and remain in Kigali time; a failed refresh does not relabel old data as current.

Historical note from 27 October: live request verification was attempted both through the web tool and the shell. This session's network restrictions prevented reaching the JSON endpoint. API behavior was tested with deterministic HTTP responses, including 503, malformed JSON and timeout; screenshots are fixtures, not claimed live observations. `dart run check_weather.dart` fetches all four cities and prints the current Huye/Kigali comparison when network is available.

## Storage selection

- Flutter's SQLite recipe: https://docs.flutter.dev/cookbook/persistence/sqlite
- SharedPreferences documentation: https://pub.dev/packages/shared_preferences

`sqflite` supports native iOS/Android and fits the user's SQLite requirement. Awaited writes and transactions protect task persistence and delete/undo consistency. SharedPreferences is used only for selected city, matching step 7; important task data stays in SQLite. The package documentation warns against using SharedPreferences for critical records.

No service credentials, telemetry SDK, account system or GPS permission is necessary. Each installed application has its own sandbox and its own database; they share source code, not user data. There is no cloud backup or cross-device sync.

## Design research and decisions

Apple's Weather reference: https://support.apple.com/en-au/guide/iphone/iph1ac0b35f/26/ios/26

The primary pattern is location → current temperature → hourly strip → daily forecast → details. Daybook uses the same typography, spacing and cards, with task notes inspired by the user's notebook/to-do request. The Refero and Apple design skills informed reference locking, system typography, minimum touch areas, consistent icon semantics and native scrolling/sheets. No Refero MCP tool was available, so bundled craft references and the supplied/official references were used.

Colors: near-black `#17191B`, white and neutral black-opacity surfaces; muted blue `#3E6D8C` is the only chromatic accent. Offline state uses blue plus explicit icon/text instead of the guide's yellow, honoring the requested palette. The app icons are original code-native sun/notebook marks, generated by `tool/generate_icons.dart`.
